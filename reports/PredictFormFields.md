# Полета за Predict формата

## Общо: **36 полета** (всички задължителни)

---

## 📋 1. Идентификатори на продукта/магазина (5 полета)

### Категорични полета - избор от dropdown/select:

| Поле       | Тип    | Описание       | Валидни стойности                                |
| ---------- | ------ | -------------- | ------------------------------------------------ |
| `item_id`  | string | ID на продукта | HOBBIES_1_001, HOBBIES_1_002, ..., HOBBIES_1_010 |
| `dept_id`  | string | Отдел          | HOBBIES_1, HOBBIES_2                             |
| `cat_id`   | string | Категория      | HOBBIES                                          |
| `store_id` | string | ID на магазина | CA_1                                             |
| `state_id` | string | Щат            | CA                                               |

**Забележка:** Ако потребителят въведе стойност, която не е в списъка, моделът я третира като "UNKNOWN", но е препоръчително да се използват само валидни стойности.

## 🎯 Препоръки за UX в уеб формата

### Автоматично попълване:

1. **Избор на дата** → автоматично изчислява всички календарни полета (wm_yr_wk, wday, month, year, quarter, day_of_month, day_of_year, week_of_year, is_weekend, is_holiday)
2. **Избор на item_id** → backend API извлича от исторически данни:
   - Всички sales_lag\* полета
   - Всички sales_rmean* и sales_rstd* полета
   - Текущата цена и price\_\* характеристики

### Ръчно попълване:

- Идентификатори (item_id, dept_id, cat_id, store_id, state_id)
- Събития (event_name_1, event_type_1)
- SNAP индикатори (snap_CA, snap_TX, snap_WI)
- Продажна цена (sell_price) - може да се остави на backend да я извлече

### Валидация:

- Всички числови полета трябва да са валидни числа (не null)
- Категоричните полета трябва да са от валидния списък (вж. preprocessing_metadata.json)
- Булевите полета трябва да са 0 или 1
